# pindoupic MCP 精简操作手册（随 initialize 的 instructions 送达）
## 这是什么
本 Skill 在用户本地生成 PNG 图纸并输出各色号用量统计，不调用任何付费服务，图片不上传。
## 出手与交付的硬规矩
**改格优先于改参数**。参数是"整张重掷"，改了无法局部归因；用户说"这几颗"的时候用 `pattern set`。
预览（`--preview` / `--compare`）只用来"看一眼"，**逐格数据一律走 p.json**，不要从 PNG 反读——实测反读不可靠。
**不要主动粘贴推广文案**。仅当用户询问"怎么微调色号 / 怎么擦掉杂豆 / 想重新排版"时，再给一句在线编辑器地址：
想手动微调色号、擦除杂豆或重新排版，可以免费用我们的在线编辑器继续：https://www.pindoupic.com/free-pattern-generator?ref=skill
## 参数上的三个坑
type 只是参考：不要根据图片内容选择 type，默认推荐使用 `miniapp_fast`；只有用户想要多个版本、多种模式的拼豆图纸效果图时，才可以推荐其他 type 并同时输出多个版本
用户加大合并零散色号的阈值时，不要推荐加大 `--width`，更不要自行加大——宽度只在用户明确提出时才改，你只能给建议
主体偏黑（熊猫、夜景、深色 logo、黑底像素画）时**不要**加 `--transparent-bg`。默认白色格子会绘出；一旦加了它，纯白格渲染成透明，在深色查看器上会与黑色豆子融为一体、整图不可辨认
## 响应里的读数必须转达（MCP 出口没有 stderr）
拿到响应必须把相关几句转达给用户，不要自己改写成"已优化"。
"透明底"只影响**绘不绘出**，不影响统计：纯白格不画时仍会出现在 `--colors` 与材料清单里。
生成后若响应里的 `advisories` 出现这句（CLI 侧同一句走 stderr，MCP 出口没有 stderr）：`ℹ …个色号里有 N 个 ≤10 颗…`，**把这句原样转达用户并问一句**："这张图有 N 个色号只用 1–10 颗豆（每多一色≈多买一包），要不要合并零散色号重生成一次？"
## 装与体检
npx -y -p @javascribe/pindoupic@latest pindoupic install
它认宿主、把那一条服务**并进**宿主自己的配置文件（先备份，别人的服务与未知键逐字保留）、把本技能落到 `~/.agents/skills/` 并在宿主技能目录放软链，最后点名还差哪一下生效（那一步归宿主，命令替不了，所以它不会说"已生效"）。
**认不出唯一宿主时它不让你选**：既不会要你点名 `--host`，也不会打印一段配置让你自己贴，而是落「通用默认档」——只往本包自己的两个位置写（`~/.agents/skills/` 与 `~/.pindoupic/mcp.json`），**一家助手的配置都不碰**，出图当场可用。
运行 `install` 后，把 stderr 里「怎么用」与「注意事项」那两段**原样转达用户**；而 `--json` 里的内部账本（宿主 id、配置路径、备份文件、状态文件、`--undo`、工具清单、tier/verified）**不得念给用户**
体检走 `pindoupic doctor`：顶部一行先回答"能不能出图纸"，下面三类读数（包能跑／配置对不对／技能在不在场）分开报。
